# Migration baseline reset (2026-04-29)

The `migrations/` history was squashed into a single `0000_baseline.sql` to eliminate `meta/` snapshot drift. The old 0001–0013 hand-written migrations and their partial snapshots were deleted. Git history retains them.

After this change, **every environment must be wiped and re-bootstrapped**. The new baseline is ~33 KB of pure DDL and matches `src/models/Schema.ts` exactly.

## Why this was needed

- `meta/_journal.json` had entries for migrations 0–12, but `meta/*_snapshot.json` files only existed for 0–6 because hand-written migrations don't generate snapshots.
- Every `npm run db:generate` diffed the current schema against the stale `0006_snapshot.json`, surfacing false "rename column?" prompts that forced manual hand-writing — a feedback loop that kept the drift growing.
- A single baseline, generated by drizzle-kit, gives us a fresh snapshot. Future `db:generate` runs now produce normal incremental migrations with no rename prompts.

## Reset commands per environment

### Local (PGLite)

```bash
# Stop the db-server (Ctrl+C in the terminal running npm run db-server:file)
rm -rf local.db
npm run db-server:file
# In a second terminal:
DATABASE_URL="postgresql://postgres:postgres@127.0.0.1:5432/postgres" \
  npx tsx src/scripts/seed.ts --orgId=org_xxxxx
```

### Neon preview branch

```bash
# Connect to the preview branch (use the pooled connection string from .env.preview)
source .env.preview
psql "$DATABASE_URL" <<'SQL'
DROP SCHEMA IF EXISTS public CASCADE;
DROP SCHEMA IF EXISTS drizzle CASCADE;
CREATE SCHEMA public;
SQL

# Vercel will auto-run the new baseline on the next request via runMigrations().
# Then reseed:
npx tsx src/scripts/seed.ts --orgId=org_xxxxx
```

Alternative: in the Neon Console, delete the `preview` branch and recreate it from `main`. Do this **after** `main` is reset, otherwise you'll inherit production data with the old schema.

### Neon main (production)

Coordinate this with the team — there's no rollback after the SQL block runs.

```bash
# Use the pooled DATABASE_URL for the main branch
psql "$PRODUCTION_DATABASE_URL" <<'SQL'
DROP SCHEMA IF EXISTS public CASCADE;
DROP SCHEMA IF EXISTS drizzle CASCADE;
CREATE SCHEMA public;
SQL

# Trigger a fresh deploy. runMigrations() applies 0000_baseline on first request.
# Then seed the production org:
DATABASE_URL="$PRODUCTION_DATABASE_URL" \
  npx tsx src/scripts/seed.ts --orgId=org_production_xxxxx
```

### Order of operations

1. Merge the PR containing `migrations/0000_baseline.sql`.
2. Reset local first (cheapest, validates the baseline applies cleanly).
3. Reset Neon preview, redeploy a preview, smoke-test.
4. Reset Neon main, redeploy production, smoke-test.

## Going forward

`npm run db:generate` should now produce clean incremental migrations every time. If it ever prompts about renames again, the cause is a real schema rename in `Schema.ts` — answer correctly and don't bypass to a hand-written file.

If a hand-written migration is genuinely needed (e.g. a data backfill that drizzle-kit can't express), follow this workflow to keep `meta/` in sync:

1. Run `npm run db:generate -- --custom --name=my-data-fix` first — this writes an empty SQL file *and* a fresh snapshot.
2. Fill in the SQL.
3. Apply with `npm run db:migrate`.

The `--custom` flag is the supported escape hatch and avoids the snapshot-disconnect that caused this reset.
